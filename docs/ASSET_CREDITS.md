## Собственные ассеты

| Ресурс | Автор | Лицензия | Файлы |

Спрайты в `assets/sprites/` — реальный арт, а не заглушки: все восемь файлов
нарезаны из CC0-пака Ninja Adventure скриптом `tools/import_ninja_sprites.py`
(карта источников — в таблице «Ninja Adventure: что взято» ниже). Что импорт
действительно лёг на диск, а не остался в намерениях, доказывает доминирующий
цвет тайла травы: **RGB(173, 188, 58)** (среднее по тайлу —
RGB(172.1, 187.6, 57.9)), тогда как у процедурной заглушки он был
RGB(74, 108, 62). `tools/gen_sprites.py` в репозитории остаётся, но только как
генератор-запасной вариант: он умеет восстановить прежние процедурные картинки,
если пака под рукой не окажется, и в текущей сборке не запускается.

### Звуки

Все восемь файлов сгенерированы процедурно скриптом `tools/gen_audio.py`
(чистый Python 3, только стандартная библиотека), CC0 / собственная работа,
не содержат сторонних сэмплов. Ничего не скачивалось и не заимствовалось.

| Файл | Что звучит | Длительность | Пик |
| --- | --- | --- | --- |
| `assets/audio/hit.wav` | Игрок попадает по врагу: всплеск шума с быстрым спадом | 90 мс | −6 dBFS |
| `assets/audio/hurt.wav` | Игрок получает урон: низкая синусоида 320→120 Гц | 140 мс | −6 dBFS |
| `assets/audio/enemy_die.wav` | Смерть врага: нисходящий шум плюс синус 220→70 Гц | 260 мс | −6 dBFS |
| `assets/audio/pickup.wav` | Подбор лута: двухтоновый блип 880→1320 Гц | 120 мс | −6 dBFS |
| `assets/audio/cast.wav` | Успешное применение умения: свип 400→900 Гц с лёгким шумом | 180 мс | −6 dBFS |
| `assets/audio/ui_click.wav` | Открытие/закрытие панели, меню: клик 1000 Гц | 40 мс | −13 dBFS |
| `assets/audio/step.wav` | Шаг по земле: мягкий гулкий шум | 50 мс | −6 dBFS |
| `assets/audio/boss_roar.wav` | Босс уходит во вторую фазу: низкий пил 90 Гц с вибрато | 500 мс | −6 dBFS |

Формат общий: PCM 16 бит, моно, 22050 Гц. Каждый файл нормализован к своему
пику и жёстко ограничен сверху до 32760 отсчётов, поэтому ни один сэмпл не
достигает ±32767 — клиппинга нет ни в одном звуке. `ui_click` намеренно тише
остальных: клик меню наравне с ударом звучит оглушающе.

Музыки в срезе **нет**: ни одного музыкального файла не сгенерировано и не
подключено. `AudioManager.play_music()` существует как интерфейс, но вызывать
его пока не на чем — трек добавляется отдельной задачей.

`step.wav` сгенерирован, но к событиям пока не подключён: в срезе нет шаговой
каденции игрока, от которой его можно было бы взять. Подключается вместе с
анимацией ходьбы.

Скрипт идемпотентен: повторный запуск перезаписывает файлы побайтово одинаково
(свой сид на каждый звук), поэтому ассеты воспроизводимы из закоммиченного
генератора.

### Ninja Adventure: что взято

Восемь спрайтов в `assets/sprites/` — реальный арт из
`assets/assets4/ninja_adventure_asset_pack.zip` (автор **Pixel-Boy / Sparklin
Labs**, лицензия **CC0 1.0**). Файлы нарезаны скриптом
`tools/import_ninja_sprites.py`; размеры и имена сохранены, поэтому игровой код
не менялся. Распакованный пак сверен с архивом побайтово (`md5` совпали у
`Backgrounds/Tilesets/TilesetNature.png` и
`Actor/Character/NinjaRed/SpriteSheet.png`), ничего не скачивалось.

Воспроизводится одним запуском:

```bash
unzip -q assets/assets4/ninja_adventure_asset_pack.zip -d /tmp/ninja
python3 tools/import_ninja_sprites.py --src /tmp/ninja
```

Скрипт детерминирован и идемпотентен: три последовательных запуска дали
побайтово одинаковые PNG — `md5` всех восьми файлов во всех трёх прогонах
совпали. Из сглаживания только nearest-neighbour, размытия нет.

**Порядок столбцов листов персонажей.** Листы персонажей — 64×112 = 4 столбца ×
7 строк по 16×16 (замерено по `pixelWidth`/`pixelHeight` у NinjaRed, Villager и
Hunter). README пака заявляет порядок столбцов down/right/left/up, но замер
пикселей ряда 0 даёт реальный порядок **DOWN(col0) / UP(col1) / LEFT(col2) /
RIGHT(col3)**:

| столбец | светлых «глазных» пикселей (rows 2–8) | центроид глаз по X | вывод |
| --- | --- | --- | --- |
| col0 | 16 в 6 разных столбцах | — | два глаза спереди → **DOWN** |
| col1 | 0 | — | затылок без черт → **UP** |
| col2 | 10 | 4.5 | глаз слева, смотрит влево → **LEFT** |
| col3 | 10 | 10.5 | глаз справа, смотрит вправо → **RIGHT** |

Нарезка использует замеренный порядок, а не заявленный. Лист `Dog` — 32×16
(2 кадра, только вид сбоку), `LittleTreasureChest` — 32×16 (2 кадра: закрыт /
открыт), `LifePot` — 9×11, `GoldCoin` — 7×7.

| Файл проекта | Размер | Источник в паке | Ячейка | Примечание |
| --- | --- | --- | --- | --- |
| `player.png` | 64×16 | `Actor/Character/NinjaRed/SpriteSheet.png` | (0,0) DOWN, (16,0) UP, (48,0) RIGHT, (0,0) резерв | ряд 0 — стойка |
| `wolf.png` | 16×16 | `Actor/Animal/Dog/SpriteSheet.png` | (0,0) | лист только вид-сбоку, взят кадр 0 |
| `archer.png` | 16×16 | `Actor/Character/Hunter/SpriteSheet.png` | (0,0) | |
| `npc.png` | 16×16 | `Actor/Character/Villager/SpriteSheet.png` | (0,0) | |
| `chest.png` | 16×16 | `Items/Treasure/LittleTreasureChest.png` | (0,0) | закрытый сундук |
| `potion.png` | 16×16 | `Items/Potion/LifePot.png` | 9×11 по центру | |
| `coin.png` | 8×8 | `Items/Treasure/GoldCoin.png` | 7×7 → nearest-neighbour 8×8 | |
| `tiles.png` | 64×16 | трава ← `Backgrounds/Tilesets/TilesetField.png` (16,64); земля ← `Backgrounds/Tilesets/TilesetField.png` (16,16); камень ← `Backgrounds/Tilesets/TilesetNature.png` (288,240); дерево ← `Backgrounds/Tilesets/TilesetNature.png` (192,144) | порядок в листе: grass, dirt, stone, tree | все четыре тайла 100 % непрозрачны; дерево наложено поверх травы — см. абзац «Композит дерева» ниже |

**Композит дерева.** Ячейка дерева `TilesetNature.png` px(192,144) — куст,
нарисованный на пустом фоне: замер дал **118 прозрачных пикселей из 256**
(opaque_frac 0.539), включая оба крайних столбца целиком. Нарезанная прямо в
атлас, она рисовала чёрный квадрат вокруг каждого дерева в `TileMapLayer`.
Поэтому каждый тайл проходит через `ensure_opaque()`: под него подкладывается
непрозрачная трава, а сам тайл накладывается поверх по правилу source-over —
целочисленная математика, без размытия и без передискретизации. Замер `tiles.png`
после импорта:

Тайл дерева собирается вариантом `b` скрипта `tools/import_ninja_sprites.py`
(`--tree-variant`): куст поверх сплошной подложки RGB(26, 48, 30), затем каждый
непрозрачный пиксель затемнён на 25 % целочисленным умножением — средний тон
61.9 против 167.5 у травы по Rec.601, то есть на 105.6 единицы темнее, при
100 % непрозрачности; варианты `a` (89.6) и `c` (97.2) замерены и отвергнуты как
светлее.

| тайл | opaque_frac | средний тон | доминирующий цвет |
| --- | --- | --- | --- |
| grass | 1.000 | 174.9 | RGB(173, 188, 58) ×252 из 256 |
| dirt | 1.000 | 184.0 | RGB(255, 173, 93) ×252 |
| stone | 1.000 | 128.8 | RGB(141, 151, 127) ×131 |
| tree | 1.000 | 149.2 | RGB(173, 188, 58) ×163 — куст на траве |

Трава, земля и камень непрозрачны уже в исходнике, так что `ensure_opaque()`
не меняет их побайтово — они равны исходным ячейкам. Для справки по тем же
тайлсетам: в `TilesetField` полностью непрозрачны лишь 5 ячеек из 75 (обе
взятые оттуда — трава и земля — среди них), а в `TilesetNature` — 23 ячейки из
504, и ячейка дерева (12,9) среди них не оказалась: полностью непрозрачного
куста в паке просто нет, поэтому подкладка травы — единственный способ убрать
чёрный квадрат. Единственный тайл, получивший траву под низ, — дерево: его
крайние столбцы col0, col1, col14 и col15 после композита **побайтово
совпадают** с теми же столбцами тайла травы, поэтому шов с травой не читается.
 На скриншоте игрового мира
(`PEPEL_SCREENSHOT`) число пикселей с яркостью < 25 в области игры — 211 из
108 480 (0,195 %), и это контурные пиксели спрайтов цвета
RGB(13, 25, 16) / RGB(20, 17, 11) / RGB(12, 23, 27), а не фон тайлов.

Камень выбран как мшистый серый камень (lum 128.8, самый бесшовный); прежняя
ячейка (144,96) оказалась почти белым снегом (lum 241.3). Дерево — цельный
округлый куст с коротким стволом: по замеру он занимает строки 0–13 и столбцы
2–13, то есть имеет пустые левый/правый поля, и потому тайлится отдельными
кустами; прежняя ячейка (0,16) была одним квадрантом дерева 2×2 и давала
полосатые колонны.

Остальные внешние файлы (тайлы подземелья, боссы, VFX, шрифты) пока **не
подключены** — таблица источников выше фиксирует доступность и правила, а не
факт использования.

## Шрифты

Используется `SystemFont` с цепочкой `Helvetica Neue → Arial Unicode MS →
Arial → DejaVu Sans`, то есть системные шрифты, не встроенные в игру. Для
релиза нужен явно лицензированный шрифт с кириллицей.
