# План тестирования

Дата: 2026-11-18. Движок: Godot `4.7.2.stable.official.ed1daf0bf`.
Это план: что проверяем, какой командой, какой результат считается нормой.
Фактические прогоны — в `docs/TEST_REPORT.md`, запуск бота — в `BOT_GUIDE.md`.

## 1. Назначение и границы

Объект проверки — вертикальный срез: одна зона, один квест `q01_ash_wolves`,
один NPC, два типа врагов (`ash_wolf`, `ash_archer`), инвентарь с четырьмя
быстрыми слотами, три слота сохранений, HUD, журнал, карта.

План отвечает на три вопроса: не сломалась ли логика, проходит ли игровой путь
от NPC до награды, и что по-прежнему обязан посмотреть человек.

Вне области проверки сознательно: 5 зон, 18+ врагов, 4 босса, 9 NPC,
12–16 квестов, магия и статусы, торговля, звук, экспорт под Windows,
переназначение клавиш, геймпад кроме атаки на `X`, производительность на
слабом железе. Этого в коде нет — проверять нечего.

## 2. Уровни проверки

```bash
TESTS='godot --headless --path . --script res://tests/test_core.gd'   # $TESTS
```

| Уровень | Что покрывает | Команда | Ожидаемый результат |
| --- | --- | --- | --- |
| unit | Чистая логика: `DamageResolver`, `GameState`, `QuestManager`, `SaveManager` | `$TESTS` | `failures: 0`, строка `got 23/23` |
| integration | `main.tscn` целиком: враги, HUD, журнал, карта, быстрый слот, умение | `$TESTS` | те же строки, `SCRIPT ERROR` нет |
| smoke | Чистый запуск сцены без тестов | `godot --headless --path . --quit-after 120 2>&1 \| grep -cE 'ERROR\|SCRIPT ERROR'` | `0` |
| bot | Реальный игровой путь через `InputSource` | `godot --headless --path . -- --bot=BOT-001` | `[bot] BOT-001 -> PASS (...)` |
| soak | 75 с блуждания по карте с боями | `godot --headless --path . -- --bot=BOT-010` | `[bot] BOT-010 -> PASS (...)` |
| manual | Ощущение управления, баланс, читаемость, UI на 480x270 | `PEPEL_SCREENSHOT=/tmp/shot.png godot --path .` | оценка человека, не автопрогон |

## 3. Инвентарь тестовых групп

Все 23 группы живут в одном файле `tests/test_core.gd` и запускаются **одной**
командой `$TESTS`: фильтра по группе в коде нет, отдельные группы запустить
нельзя. Каждая группа помечает себя в счётчик `completed`, и в конце стоит
проверка `every test group ran to completion (got 23/23)` — если группа упала
до своей метки, счётчик это покажет.

Команда для каждой строки таблицы: `$TESTS`.

| Группа | Что доказывает |
| --- | --- |
| `damage_dedupe` | первый удар по `hit_id` применяется, повтор того же `hit_id` — нет; цель получает ровно один удар, HP 100 → 90 |
| `damage_defense` | без защиты проходит полный урон (10), защита в ответе `0` |
| `inventory` | стек докладывается в один слот, дубликата слота нет, удаление работает, снять больше чем есть нельзя |
| `xp_gold` | level-up по порогу XP, золото начисляется и тратится, уход в минус отклонён с сохранением баланса |
| `quick_slots` | действия `quick_slot_1..4` на клавишах `1..4`, значения по умолчанию, отказ на экипировку и вне диапазона, назначения возвращаются из сохранения, битые данные откатываются к умолчаниям; реальный `3` выпивает одно зелье и лечит 40 HP, `4` по пустому слоту ничего не тратит и даёт тост `Слот 4 пуст` |
| `save_load` | round-trip слота 2: золото, инвентарь, экипировка, HP, состояние квеста |
| `corrupt` | битый первичный файл без бэкапа отклоняется с ошибкой `corrupt_and_no_backup`, а не `empty_slot` |
| `slot_isolation` | битый первичный с валидным бэкапом восстанавливается из бэкапа, без бэкапа отклоняется; после теста в слоте 3 нет следов |
| `save_fixtures` | три фикстуры `tests/fixtures/saves/` грузятся через `SaveManager`: v1 полный, v0 без блока квестов (миграция даёт пустой блок), v0 разреженный (поля из дефолтов); сохранение со схемой 99 отклоняется как `newer_schema_99` и остаётся неизменным |
| `quests` | старт, готовность после нужного числа убийств, награда ровно один раз, повторная сдача отклонена без повтора золота |
| `ranged` | дальнобойный враг реально порождает снаряд (`projectile.gd`) |
| `melee` | ближний враг показывает телеграф, хитбокс не открыт все 180 кадров |
| `human_input` | настоящий `InputEventKey` двигает героя, отпускание останавливает; `J` открывает журнал и не начинает атаку; `Space` — рывок; ЛКМ — атака; открытое UI блокирует движение |
| `map` | действие `map` на `M`, сетка 52x32, туман (исследовано меньше карты), ≥3 метки с непустыми `id`/`kind`, `cell_at` для границы/игрока/за пределами; `M` открывает и закрывает карту, `ui_blocking` включается и снимается, движение возвращается |
| `ability` | действие `ability` на ПКМ, списывает ровно 10 маны, входит в `DASH`, на кулдауне не тратит ману, без маны не срабатывает, после кулдауна работает снова |
| `diagonal` | движение по диагонали (`D`+`S`) не быстрее кардинального (`D`): расхождение меньше 12 %, кардинальная скорость больше 20 px/s |
| `camera` | у игрока есть `Camera2D`, `limit_right`/`limit_bottom` покрывают карту, сглажение включено, игрок — ребёнок `World` |
| `scene` | `main.tscn` грузится, игрок есть, врагов ≥2, интерактивных объектов ≥2 |
| `world_composition` | мир спавнит ≥5 `ash_wolf` и ровно одного `ash_archer` с именем `ArcherA`, его `kind` отличается от волчьего |
| `bot_quest_target` | выбор цели по квесту возвращает `ash_wolf`, пропуская подсаженного рядом культиста, и `null` для неизвестного `quest_id`; слепой выбор на культисте бы попался |
| `projectile_wall` | снаряд гаснет о стену/дерево (`TileMapLayer`) и не наносит игроку урона; контрольный снаряд над открытой землёй летит все 30 кадров |
| `input_isolation` | идёт первой, до групп с реальным вводом: стартовый сброс возвращает InputMap к известному состоянию — любой заранее лежащий `user://settings/controls.json` удалён, `interact` снова на `E`; группа сажает реальный ребинд `interact`→`F` движком и доказывает, что этот сброс его нейтрализует (вернулся `E`, файл удалён); в конце прогона сброс повторяется, и `controls.json` не остаётся |
| `input_bindings` | ребинд отклоняет действие вне `REBINDABLE`, `null` и занятую клавишу; `interact`→`F` применяется и снимает `E`; `save_bindings` пишет файл вне `user://saves`, `load_bindings` возвращает привязку из файла; `reset_action` возвращает `E`; битый файл не ломает привязки |

## 4. Как читать результат

- `$TESTS` печатает `checks: N  failures: M`. Норма — `failures: 0`.
  Актуально на 2026-11-18: `checks: 210  failures: 0`.
- Код возврата у Godot **не** является доказательством: движок выходит `0`
  и после ошибок времени выполнения. Смысл имеет только вывод.
- Любая строка `ERROR` или `SCRIPT ERROR` в выводе — прогон считается
  проваленным, даже если `failures: 0`.
- Дымовой прогон: `--quit-after 120` и `grep -cE 'ERROR|SCRIPT ERROR'` → `0`.
- Бот: последняя строка `[bot] BOT-xxx -> PASS (заметки)` и `RESULT: PASS`
  в `user://debug_runs/<run_id>/summary.md`. `PASS` без этих строк — не PASS.
- Тесты прогонялись трижды подряд без провалов; BOT-002 и BOT-010 — трижды
  подряд `PASS` (см. `docs/TEST_REPORT.md` §2).

## 5. Ручная проверка (автоматом не покрыто)

- Ощущение управления: ускорение, торможение, отзывчивость рывка, читаемость
  телеграфа волка и полёта стрелы.
- Баланс: хватает ли зелий на цикл квеста, не умирает ли игрок с одного
  промаха, не тривиален ли бой.
- Читаемость HUD на 480x270 (viewport, integer stretch, окно 1440x810):
  ничего не обрезано, подсказка влезает, четыре быстрых слота видны.
- Скриншоты из настоящего окна (headless обрезанный UI не покажет):

```bash
PEPEL_SCREENSHOT=/tmp/world.png godot --path .
PEPEL_SCREENSHOT=/tmp/dialogue.png PEPEL_SCREENSHOT_UI=dialogue godot --path .
PEPEL_SCREENSHOT=/tmp/inventory.png PEPEL_SCREENSHOT_UI=inventory godot --path .
PEPEL_SCREENSHOT=/tmp/journal.png PEPEL_SCREENSHOT_UI=journal godot --path .
PEPEL_SCREENSHOT=/tmp/map.png PEPEL_SCREENSHOT_UI=map godot --path .
PEPEL_LOAD_SLOT=1 godot --path .   # загрузка слота на старте
```

- Живой проход руками: `WASD`, `E` разговор, `1..4` зелья, `J` журнал,
  `M` карта, `Esc` пауза, `ПКМ` умение, `Space` рывок, ЛКМ атака.

- Экспорт под Windows и запуск собранного билда.
- Одна зона: переходы между зонами, сохранение позиции между сценами.
- Производительность на слабом железе, просадки кадров.
- Геймпад, кроме того что `X` есть в `attack`; переназначение клавиш.
- Watchdog, детектор циклов и нулевого прогресса, панель запуска бота,
  реплей — из ТЗ не сделано, ловушка «бот зациклился» не обнаруживается
  автоматически.

## 7. Правило регресса

После **любого** изменения прогоняется полностью всё:

```bash
godot --headless --path . --script res://tests/test_core.gd   # failures: 0
godot --headless --path . --quit-after 120 2>&1 | grep -cE 'ERROR|SCRIPT ERROR'  # 0
```

Плюс сценарии бота, которых касается правка, а при правке боя, квеста,
сохранения или пути NPC — все шесть (`BOT-001`, `BOT-002`, `BOT-008`,
`BOT-009`, `BOT-010`, `BOT-011`). Новая фича, ломающая старый тест, не
принимается: регресс важнее новой функциональности. Визуальные правки
проверяются скриншотом из окна, headless их не видит.
